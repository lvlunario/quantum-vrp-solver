# 2026-10-12 — The mixer passes, but optimization stays outside the gate

**SIMULATED NARRATIVE — independent personal project in a Norway setting; no host institution, employment, affiliation, real meeting, or external collaboration is claimed.** The Qiskit experiment described below was actually executed locally on synthetic data.

## 08:30–09:15 — Monday continuity review

The week opened by reading the runbook, project state, backlog, calendar, Friday journal, Thursday journal, and fictional collaboration plan from GitHub. Friday had converted the original QAOA paper into an explicit acceptance contract. The next task was therefore not an angle search. It was to test whether a single mixer layer means what the equations say it means.

The key convention was already source-checked: the paper uses (e^{-i\beta X}), while Qiskit defines `RX(theta)` as (e^{-i\theta X/2}). The circuit must therefore use `RX(2*beta)`. This factor can easily disappear in code while leaving a unitary-looking circuit.

## 09:15–10:00 — Simulated supervision decision

**SIMULATED NARRATIVE:** In a fictional 40-minute supervision discussion, the software-verification role asked for an oracle that did not call Qiskit gates internally. The decision was to calculate the mixer through explicit amplitude pairing: for each qubit, every pair of amplitudes whose indices differ only at that bit is transformed by the analytical two-by-two matrix. This preserves independence between implementation and reference.

The same discussion rejected a proposed grid search for today. Passing a variational result would be hard to interpret if the layer semantics were still uncertain. The revised plan was: mixer correctness first, readout semantics next, optimizer later.

## 10:00–12:00 — Implementation

I added `src/verify_qiskit_mixer.py`. It constructs six Hadamards, the verified six-RZ/fifteen-RZZ cost layer, and six RX gates. The independent path begins with 64 equal amplitudes, applies the exact energy phase directly, and then applies six analytical mixer transforms.

The first version of the beta-zero test compared the circuit with itself. That would pass without proving the mixer is an identity. I discarded that shortcut and changed the reference to the direct cost-phase vector. This was a small but important test-design failure: independence matters as much in a unit test as in a research claim.

## 12:45–14:00 — Clean execution

A fresh Python 3.12 environment installed the pinned dependency set: Qiskit 2.5.2 and NumPy 2.5.3. The deterministic command ran three predetermined angle pairs and wrote `results/2026-10-12-qiskit-mixer.json` with timestamps, versions, source and lock hashes, configuration, raw observables, checks, and limitations.

All ten checks passed. Across the three angle pairs, the largest componentwise SDK/oracle difference was (1.36\times10^{-15}). The largest normalization error was (1.55\times10^{-15}). At gamma zero, measurement probabilities stayed uniform to (1.73\times10^{-17}). At the primary nonzero pair, the mixer changed at least one basis probability by 0.03787.

## 14:00–15:15 — Mutation tests

Three intentionally broken circuits were tested. Using `RX(beta)` instead of `RX(2*beta)` was rejected. Reversing the mixer sign was rejected. Applying the mixer before the cost layer was also rejected. These are targeted defects chosen from Friday's reading; they do not measure a general mutation score.

The output also stores expected energies for reproduction, but no angle was selected because it looked favorable. There was no optimizer, sampler, transpiler, noise model, cloud job, or hardware execution.
