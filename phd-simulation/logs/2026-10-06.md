# October 6 — A cost unitary cannot move probability by itself

**SIMULATED NARRATIVE — Tuesday, 6 October 2026, Norway setting.** This is an independent personal project with no host institution. The workday and research routine below are fictional. The code execution and stored numerical output are real local computations on synthetic data. No meeting, affiliation, peer review or hardware run is claimed.

## 08:30–09:15 — Turn yesterday's caveat into a test

The fictional Tuesday begins with yesterday's narrow next question: does the audited Ising energy acquire the intended phase under cost evolution? It is tempting to add a mixer and optimize immediately, but that would combine several interfaces at once. Today's scope is deliberately smaller. The acceptance target is a diagonal operator whose phase can be predicted independently for every one of the 64 basis states.

The existing residual model remains the oracle. For each binary assignment, it computes unmet-priority cost plus the squared capacity residual. The Ising fields, pair couplings and constant are reconstructed from the earlier formulation. No sampled output is used to define correctness, and no result from a quantum optimizer is available.

## 09:15–10:30 — Coursework: translate exponentials into gate angles

The morning study block checks current IBM Quantum documentation rather than relying on memory. The documented Pauli evolution convention is \(e^{-itH}\). The RZ and RZZ definitions place the rotation angle over two in the exponent. Under those conventions, implementing \(e^{-i\gamma hZ}\) requires an RZ angle of \(2\gamma h\); the same factor applies to a \(ZZ\) coefficient and RZZ.

This detail becomes an executable contract in the new [phase-evolution source](../src/verify_phase_evolution.py). The [technical note](../docs/phase-evolution.md) records the equations, primary documentation links and the boundary between a plain-Python convention audit and a future SDK integration test.

## 10:30–12:00 — Build the independent phase comparisons

The script evaluates all 64 basis states at four angles: zero, \(\pi/17\), 0.2 and 0.7. For every state-angle pair, it compares the phase computed from the residual oracle with the phase from the Ising energy. A third route multiplies the phase contributions of the constant, each local Z term and every ZZ term, using the documented factor of two.

The implementation also removes the constant offset of 50 and checks the predicted common factor explicitly. This matters because “the offset does not matter” is too vague. It does not change relative phases or the optimizer's decision, but it does change the statevector by a global phase and still matters when reporting the original objective value.

## 12:00–12:30 — Lunch and a useful non-result

The imagined lunch discussion is with a notebook, not a collaborator. The important expectation is that the cost unitary alone cannot improve the probability of the best answer. It is diagonal in the computational basis, so it only rotates complex amplitudes. The mixer, or another interference-producing step, is what can convert relative phase into a changed measurement distribution.

This is a useful brake on visual demos. If a program reports changed computational-basis probabilities immediately after an ideal diagonal cost layer, either the initial comparison, basis labeling or implementation deserves investigation.

## 12:30–14:30 — Execute the bounded audit

The actual standard-library run produces [raw JSON evidence](../results/2026-10-06-phase-audit.json). Nine checks pass. Direct oracle and mapped phases agree for all 256 state-angle pairs. The decomposed RZ/RZZ-style calculation agrees with maximum absolute error \(1.05\times10^{-14}\), consistent with floating-point evaluation. Dropping the offset produces only the predicted common phase, with maximum residual \(1.42\times10^{-14}\).

A deterministic normalized 64-amplitude fixture retains its norm, and the largest basis-probability drift is \(1.04\times10^{-17}\). All 64 amplitudes change at \(\gamma=0.2\), but their probabilities do not. This is not QAOA performance evidence; it is a unitary-invariant check.

## 14:30–15:30 — Make two mistakes on purpose

Two fault injections test whether the oracle can reject plausible convention errors. Reversing the exponent sign mismatches all 64 states at \(\gamma=0.2\). Omitting the factor of two in the rotation angles mismatches 63 states. The one unaffected state is a property of this fixture and angle, not a loophole in the acceptance rule. These are deliberate faults introduced today, not stories about accidental bugs, and their counts cannot be generalized beyond this toy.

## 15:30–16:30 — Write the next interface boundary

R12 advances only through the algebraic phase audit. No Qiskit circuit was created, transpiled or sampled. Full-text QAOA reading remains open. The next implementation task is an SDK statevector comparison, up to global phase, with an asymmetric known basis fixture and explicit qubit ordering. Only after that check should a mixer and parameter sweep be introduced.

**Plain language:** today verified that every candidate receives the intended phase. The test also caught two common sign/angle mistakes, while confirming that a cost layer by itself cannot change which bit strings are more likely.
