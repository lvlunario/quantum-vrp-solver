## 09:10–10:20 — Coursework: predicates and empty sets

The morning exercise was to express record acceptance as a conjunction of
predicates. A valid identifier is insufficient without a valid precondition;
a valid detecting layer is insufficient without an explicit scope; an evidence
path is insufficient without knowing what has actually been verified. Passing
one predicate does not compensate for failing another.

Reading the earlier validator exposed a small but material representation
problem. Checking that every supplied resource value is zero accepts an empty
dictionary because it supplies no counterexample. It also does not distinguish
Python's Boolean false from integer zero. The new contract therefore requires
the exact resource keys and exact integer types, with a separate Boolean
baseline-reservation flag. This was a code-inspection finding, not a claim that
the earlier recorded experiment consumed unreported resources.

## 10:35–11:40 — Specify the blind-layer boundary

I wrote a project-specific machine-readable schema contract and a small
standard-library validator. Every record must name its fault class,
precondition, minimum detecting layer, known blind layers and a reason for the
blindness claim. The detector cannot also be listed as blind for that same
record. Class-to-detector rules distinguish precondition mistakes, cross-layer
inferences and collapsed application metrics.

For a concrete example, a physical oracle can correctly report each decision's
load while missing the fact that the two decisions were evaluated with
different capacities. The fault belongs at the pair precondition boundary.
Calling the physical layer blind here means its report alone cannot establish
the shared-capacity condition. It is not a universal statement that physical
checks can never reveal a problem. Detector minimality remains a documented
design argument, not a theorem established by the schema.

## 12:30–13:35 — Refuse to promote reference syntax into truth

The initial design temptation was to reuse a confirmed-evidence status. That
would make a structural checker appear stronger than it is. I instead used
PROSPECTIVE_UNEXECUTED and REFERENCE_DECLARED_NOT_VERIFIED. The second state
requires a syntactically valid synthetic path and digest, but the validator
does not open the file or check its contents.

One accepted fixture deliberately names a nonexistent synthetic file with an
all-zero digest. That is useful precisely because it is not evidence. It shows
where structural acceptance stops. Existing November 25 confirmations still
refer to their earlier evidence checks; today's schema neither repeats those
checks nor grants new confirmations. The real catalog was preserved byte for
byte, and synthetic-only identifiers prevent accidental migration.
