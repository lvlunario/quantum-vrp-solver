## 09:15–10:35 — Define the engineering boundary

I implemented a small checker whose only scientific inputs are binary load
decisions, nonnegative integer demands and an integer capacity. It computes
load directly and reports feasibility, overload and headroom. It knows nothing
about QUBO energy, slack variables, statevectors, probabilities or optimizer
claims.

That separation is essential. For the synthetic fixture, physical feasibility
is the inequality
`2x0 + 3x1 + 4x2 <= 5`. Encoding consistency instead asks whether the chosen
auxiliary slack makes `load + slack = 5`. A feasible decision with the wrong
slack fails the second test while passing the first. Treating encoding
consistency as physical feasibility would therefore reject valid operating
choices for a representation error.

Input validation is fail closed: empty or wrong-length decisions, nonbinary
values, Python Booleans, negative data and noninteger demands are rejected
before calculation.
