# Daily execution contract
## Destination and scope
Repository: lvlunario/quantum-vrp-solver. Branch: main. Work only inside phd-simulation/ except the established root navigation README.
Simulation window: 2026-09-22 through 2027-09-21 inclusive. Dates and workday episodes use Europe/Oslo. Delivery uses Asia/Manila evening.
One scheduled check each calendar day supports weekday episodes plus conditional weekends. The calendar is the reproducible seed-selected plan, not proof anything occurred.

## Each run
1. Read this file, state.json, BACKLOG.md, calendar.csv and the latest two logs from GitHub. Read repository instructions if present. Verify current branch state.
2. Determine today's Oslo date. Stop outside the window. If that date is completed, do not duplicate it; report the existing link if needed.
3. On a rest weekend: no work log and no user notification. On a selected weekend, require an active revision/experiment need near its simulated deadline; otherwise skip. Weekend work is 2–4 simulated hours, with a lighter subsequent weekday.
4. On leave weekdays: publish a short leave/handover entry and any necessary continuity note; no fake experiment. On normal weekdays follow the current phase, open blockers and theme, adapting plans to the actual state.
5. Produce a realistic dated lab journal of about 600–1000 words: morning situation, time blocks, technical problem, work attempted, what failed, fictional discussion if relevant, evidence, decision, plain-language explanation and tomorrow's work. Dates are simulated; output creation timestamps are real.
6. Include a substantial artifact: code change, executed result, paper section, derivation, annotated source note, realistic meeting minutes with decisions, or revised presentation. Do not just rewrite the diary every day. Meeting-only days are legitimate.
7. For technical claims, verify primary sources. For code, execute bounded local experiments where possible, test the concrete scientific risk and save configuration, versions, source hash, raw output and limitations. If execution is unavailable, label PLANNED/UNEXECUTED and never invent numbers or successful tests.
8. All meetings, reviews, travel, affiliations and submissions are SIMULATED NARRATIVE. Use role names, not fabricated quotations from real scientists. Cite only real publications. Manuscript drafts are educational and unsubmitted. Do not contact anyone or submit anything externally.
9. Update state.json, backlog and links in the same commit when possible. Use a non-force fast-forward update based on a freshly read parent. Never overwrite concurrent changes. Commit message: sim: YYYY-MM-DD — short specific outcome.
10. Verify a read of the committed dated log. Only then mark publication complete and give the user a brief episode summary with direct GitHub links, one technical takeaway and an optional 10-minute task. Keep the simulation progressing if Leo does not reply.

## Interruptions and honesty
If GitHub is unavailable, state that persistence failed; do not claim a commit. Retry on a later run. If a run was missed, show the actual creation date and label any reconstructed episode; never backdate a Git commit or claim unattended work took place.
Resume from actual evidence. Prefer one current episode plus a concise gap summary over mass-generating fictitious completed experiments.
Do not promise journal acceptance or a quantum advantage. A paper milestone may slip and a hypothesis may fail.
Do not install paid tools, consume paid quantum hardware, start unbounded runs, or expose resume/contact/family/financial information.
No extra plugins are necessary initially. For an actual slide deck use the available presentation skill; retain source and export in GitHub, and report any upload limitation honestly.

## Weekly and monthly variation
Monday supervisor meeting (30–45 minutes); Wednesday rotating collaborator call only when a decision requires it; Friday weekly recap and next-week plan.
Japan calls are morning Oslo; UCSD occasionally late Oslo with a later start next day. Verify timezone conversions on the story date.
Monthly review includes one pivot or risk assessment, paper progress, technical learning and reflection on career fit. Every month need not contain a breakthrough.
Quarterly seminars include slide source, speaker notes and difficult mock questions.
